# 30-Day Accelerated Roadmap

## Phase 1 (Days 1-3): Project Planning and Final Design

### Goals

- finalise project structure
- approve architecture
- define database schema
- define API contracts
- define app and dashboard flows
- confirm technical constraints and risk response

### Deliverables

- project overview and brief
- system architecture diagram
- Firestore schema
- API structure documentation
- screen blueprint
- verification workflow definition

### Outputs

- approved design package
- no code yet

## Phase 2 (Days 4-7): UI Development

### Goals

- build all app screens with dummy data
- complete navigation structure
- create reusable components
- implement responsive styling
- prepare for backend integration

### Focus

- onboarding and auth screens
- map placeholder screens
- report incident forms
- alert list and incident details
- dashboard pages with mock data

## Phase 3 (Days 8-18): Backend and Full Integration

### Goals

- implement Firebase Auth and Firestore logic
- enable incident reporting and image uploads
- integrate maps and geolocation
- enable push notifications and alerts
- build verification system
- build admin dashboard flows

### Focus areas

- authentication
- Firestore data access
- storage uploads
- incident lifecycle logic
- radius-based alerting
- hotspots and analytics
- profile and settings

## Phase 4 (Days 19-24): Testing and Hardening

### Goals

- run unit tests
- run integration tests
- performance tests
- usability checks
- fix bugs and optimize performance
- review permissions and security issues

## Phase 5 (Days 25-30): Dissertation, Presentation, and Final Demo

### Goals

- write dissertation chapters
- prepare viva questions
- prepare demo flow
- create presentation slides
- final document polish
- refine evidence and evaluation

# Daily working method

Each day should have a single core task.

## Daily format

For each day:

- Goal
- Estimated time
- Dependencies
- Files to create
- Files to modify
- Commands
- Packages
- Folder structure impact
- Architecture notes
- Testing
- Expected output
- Common errors
- Debugging process
- Definition of done
- Checklist

## Execution priorities

1. Confirm architecture before coding
2. Build UI screens early with dummy data
3. Connect Firebase after screens are stable
4. Add notifications after reporting and map flow works
5. Verify end-to-end before polish
6. Complete dissertation after stable implementation

## Risk register

- schedule compression
- backend instability
- Firebase quota or config issues
- excessive feature scope
- poor data validation
- verification bottleneck
- accessibility gaps

## Weekly milestone summary

### Week 1

- project approved
- architecture defined
- data model decided
- app/login/dashboard screens planned

### Week 2

- UI development complete
- app navigation finished
- mock dashboard complete

### Week 3

- Firebase backend integrated
- incident reporting active
- user auth complete

### Week 4

- notifications and map features live
- verification and analytics finished
- testing starts

### Week 5

- testing, bug fixes, documentation, viva prep

## Definition of done for the full project

- fully working Android app
- Firebase backend
- admin dashboard
- push notifications
- Google Maps integration
- verified incident reporting
- complete testing
- dissertation
- presentation
- viva preparation
